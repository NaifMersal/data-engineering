Govern

Who may see which data, and for how long

Governance runs across every stage: personal data enters at the sources and is copied into every layer after. PDPL and NDMO rules apply to all of them, which is why masking, access and erasure are platform features, not one model's job.
The Saudi context

PDPL and NDMO, from a data engineer's seat

PDPL (Personal Data Protection Law, enforced since September 2024; SDAIA is the competent authority): lawful purpose, data minimization, data subjects' rights (access, correction, erasure), breach notification, conditions on transfers outside the Kingdom.
NDMO data management and personal data protection standards: governance roles, data catalog, quality, and classification in four levels: Top Secret, Secret, Restricted, Public.

Discovery

Find personal data by content, then confirm with checksums

def is_saudi_id(s):            # national ID / Iqama
    if not (len(s) == 10 and s.isdigit()
            and s[0] in "12"):   # 1 citizen, 2 resident
        return False
    total = 0
    for i, ch in enumerate(reversed(s)):
        d = int(ch) * (2 if i % 2 else 1)
        total += d - 9 if d > 9 else d
    return total % 10 == 0       # Luhn

def is_saudi_iban(s):          # SA + 22, ISO 13616
    r = s[4:] + s[:4]
    return int("".join(str(int(c, 36))
               for c in r)) % 97 == 1
Column names lie (notes, ref, extra_1). Lab 4.3 finds national IDs, IBANs, mobiles and emails hiding in free-text support notes.
A regex finds 83 ten-digit candidates in the notes; the Luhn check keeps 77 real IDs and drops the tracking numbers.
Some PII has no pattern (names, addresses): declare it in the catalog.

Access control

Each role sees only what it needs

CREATE VIEW analyst.customers AS
SELECT pseudo(national_id) AS person_token,
       customer_id, city, district,
       lower(split_part(email, '@', 2))
           AS email_domain,
       created_at
FROM main.customers;

CREATE VIEW support.customers AS
SELECT customer_id, full_name, email,
       mask_mobile(mobile) AS mobile, city
FROM main.customers;
RBAC: roles get grants on schemas/views, never on raw PII tables.
Policies in the platform: column masks and row filters (Snowflake, BigQuery, Unity Catalog) apply in every tool, not just one view.
Tag-based: classify once (Secret), and the policy follows the tag to every table.

Also: derived tables and incremental models, backups, partner exports, column stats in old manifests. At scale: batch erasures weekly, or crypto-shredding (per-person keys, delete the key).
