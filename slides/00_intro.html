Course philosophy

Pipelines are software. Treat them that way.

  • Learn it, then build it. Every session is taught first, then practised in a lab.
  • Open tools, laptop scale. DuckDB, Polars, Parquet, dlt, dbt, Iceberg, Spark, Dagster. The same ideas run on any cloud.
  • Re-runnable or it didn't happen. Every load we write is idempotent and incremental.
  • Trust is a feature. Tests, contracts and lineage from Day 2, not "later".

You should already know

Python, SQL (joins, GROUP BY), basic command line, Git.

You don't need

Spark, dbt, Kafka, cloud accounts or Docker.

You will leave with

16 working notebooks, a dbt project, a lakehouse and a capstone repo.

Lab environment

Run everything before you need it

  1. Open the course repo in Google Colab or locally with uv.
  2. Run 00_setup_check.ipynb: installs packages, generates the data, smoke-tests every tool.
  3. Every notebook opens with a Setup cell and ends with Checkpoint questions.
  4. Cells marked ✱ Stretch are optional for fast finishers.
git clone https://github.com/SDAIAAcademy/data-engineering
cd data-engineering/labs
uv sync                        # creates .venv
uv run python prepare_data.py  # data/raw/
uv run jupyter lab
No Java locally? Every notebook runs on a laptop CPU except Spark (tools/spark and Lab 3.2, Java 17+): run those on Colab, where the notebook installs Java.
